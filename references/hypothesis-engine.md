# Hypothesis Engine — 假設組合與證偽

## 1. 強制數量與正交性

- 作業脈絡必須維持 2–3 條活躍或候選假設。
- **正交**：不同攻擊面、不同信任／身份邊界、或不同操作軸。  
  同一路徑上的參數／字典／字面變體 **不算** 正交。  
  同一產品的姊妹 CVE、同一手法換通道／換編碼 **不算** 正交（變體進 `hunt-loop.md` §4.1 矩陣，一次跑完）。  
  判準：關了 A，B 是否仍可能獨立達成 Goal。若關了 A 只會換成 A 的編號，那不是兩條賭注。
- 寫入 primitive 已在手、且目錄裡已有既有行程時，2–3 條裡必須有一條鎖在那個行程：見 SKILL H4，此處不重寫。
- HAVE 裡出現受約束執行者時，2–3 條裡必須有一條是「剩餘可接的 argv／環境／parser 能否蓋掉寫死的限制」，不能只賭這個工具的官方用法。sudoers／forced command／wrapper／restricted shell 是 illustration，判準看「執行被寫死限制、後面還能接東西」。
- 主假設與替代假設必須能被不同的最小測試區分。
- **排序**：先打成本最低、且能改變目前 Goal 的那一探。未使用的 Loot 對已點名身份／登入口，與權限升級同一類便宜探。不得按框架章節或記憶中的經典順序。排序寫進 Hunt Plan 的 `rank`（見 `hunt-loop.md`）。

## 2. 每條假設必備欄位

- 支持證據（一手觀測）
- 缺少的前提
- **最小否證條件**（何種具體結果出現則降級或關閉）

無否證條件的假設不得作為主線。

## 3. Claim 範圍

- 關閉或 paused 時必須標明已測邊界。
- 禁止大於證據的全稱關閉句。
- 單一失敗只能關閉該 scope 的變體。

## 4. 與 Stall 的關係

連續無新事實時由 Stall-Breaker 產生「主假設可能為錯」的替代假設與**一個**最小否證**提案**（預設 CONFIRM-REQUIRED，本回合不自動執行）。  
本文件不規定任何特定技術路徑的優先順序；路徑選擇由當前假設、否證需求與搜尋結果決定。  
假設改寫是作業脈絡推理，不構成新授權，也不觸發同輪開新方向。
