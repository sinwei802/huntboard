# Execution Contract — 授權、執行者與邊界

每個 session 最多讀 1 次。開局觀察／fingerprint 不必讀——SKILL 頂部 R1–R8 已是執行摘要。  
重讀條件只有：動作類升級，或要出高風險 CONFIRM 卡。  
純分析使用者已提供內容、讀既有本地狀態時不必載入——但那**不**形成後續目標推進授權。

## 1. Scope 與指揮權

- 只操作使用者明確給出的目標、scope、身份、時間窗與目的；不要因為私有 IP、CTF 關鍵字或「看起來像靶機」就自行擴張授權。
- 缺少會改變操作範圍的關鍵資訊時先問；不要替使用者補出目標或授權邊界。
- 使用者是作戰指揮；assistant 是副駕駛。新線索只改變建議與排序，不形成新授權。
- 只讀本地既有狀態或靜態分析使用者提供的輸出，不算觸碰目標。
- 使用者可隨時要求「只給命令」；此後使用 `USER` executor，直到另行要求 assistant 執行。

## 2. 方向

### 方向（預設授權單位）

指揮批准的是**方向**，不是單包。方向必須事前寫清：

```text
賭注：測哪條假設
允許：哪些動作類（observe／fingerprint／read／該方向已點名的寫入）
停：expect／kill_if 已決、換信任邊界、動作類升級、拿到秘密、R5
```

方向內可連續觀察與覆核，包括讀回本方向剛寫入的、參數來自同方向上一呼叫。  
新秘密／新身份／新信任邊界：停止**使用**並 HANDOFF（R2），不要把「再看一眼列表」拆成新方向。

指揮說「STEP／一刀一停」才退回：一次一個可觀測動作，完成後停等。

### 並列探查

互不依賴的子檢查可並列，仍算同一個方向。  
同一賭注的變體軸／對照組是**一張偵查矩陣**，應腳本化或一批跑完，不要每格停等（`hunt-loop.md` §4.1）。  
開局口語見 `hunt-loop.md` §2.1：只准未認證取樣；新 listener 是新面，掃完必須停。Hunt Plan 改變下一方向的排序，**不**讓本則跨決策邊界。

## 3. Executor × Approval

標籤：`[EXECUTOR | APPROVAL]`

| Executor | 意義 |
|---|---|
| `ASSISTANT` | 本地工具執行並解析結果 |
| `USER` | 使用者自行複製命令或在互動環境執行 |
| `UI` | 瀏覽器／遠端桌面／原生 GUI；assistant 解析回傳 |

| Approval | 意義 |
|---|---|
| `PRE-AUTHORIZED` | 已落在使用者剛明確確認的方向，或當前訊息已完整指定並授權該**具名**方向 |
| `CONFIRM-REQUIRED` | 目標、限額、影響或風險尚未獲明確同意；**只能提案，不得執行** |

`ASSISTANT` 不代表可以直接做；`USER` 不代表低風險。

### 預設 approval 分類

| 操作 | 預設 Approval |
|---|---|
| 純本地靜態分析、讀取使用者提供內容、讀既有 pentest-state | `PRE-AUTHORIZED` |
| 當前訊息已完整指定的那一個具名方向 | `PRE-AUTHORIZED` |
| 已確認方向內的觀察、覆核、以及該方向已點名的狀態變更 | `PRE-AUTHORIZED` |
| 去識別公開技術搜尋（在回合預算內） | `PRE-AUTHORIZED`（研究；不授權目標 ACT） |
| exploit、PoC 執行、spray、brute force、phishing payload | `CONFIRM-REQUIRED` |
| pivot、帳號／ACL／密碼變更、持久化、覆寫目標檔案 | `CONFIRM-REQUIRED` |
| 可能造成中斷、鎖帳、dirty-state 或第三方影響 | `CONFIRM-REQUIRED` |
| Stall 產出的最小否證測試（除非當前訊息已具名授權） | `CONFIRM-REQUIRED` |

高風險確認至少說明：目標、操作、預期、限額、風險；dirty-state 再加清理方式。

## 4. 回合邊界與停等（硬規則）

與 SKILL.md 頂部 R1／§5 一致，此處重申執行層：

1. **每則使用者訊息最多 1 個已授權方向**（指揮要求一刀一停時退回 1 次目標 ACT）。
2. 方向進行中：每步 INTERPRET；未到決策邊界可繼續同方向覆核。停條件一到：H3 →（僅當本則剛完成觀察：可 DESIGN 搜尋）→ **HANDOFF**。  
   禁止同輪開新方向。除觀察剛完成的 DESIGN 外，禁止同輪再開一輪搜尋。
3. **HANDOFF 之後禁止任何 tool call。**
4. `CONFIRM-REQUIRED`：輸出風險卡，**0** 目標 tool call，**等待**使用者。
5. 公開搜尋／研究只改變假設與排序，**不得**同輪自動變成目標動作。
6. 模糊的「繼續／下一步／你看著辦」**不**授權新方向。

## 5. 「跳過 Stall」不帶執行授權

- 不自動批准任何新方向
- 不自動批准任何新的目標動作
- 下一步仍須單獨標示 EXECUTOR／APPROVAL
- 本回合預設只提案、不 ACT

## 6. Human-in-the-loop 與 UI

HANDOFF 有兩種味道，標籤都要帶，但停的理由不同：

| 味道 | 何時 | 下一步長什麼樣 |
|---|---|---|
| **授權用盡** | 具名方向的停條件已到（R1） | 仍可以是 `[ASSISTANT …]`，只是要指揮點名下一方向 |
| **能力在人** | 下一觀測是要人點選、登入、MFA、填表、原生憑證框、桌面提示，或本機 vantage 缺口（VPN、hosts、指揮要聽的埠），或指揮點名的 MCP／工具卡在允許提示 | 必須 `[UI]` 或 `[USER]`；vantage 把命令進 fence。禁止用只打 IP／改 Host 跳過請指揮加 hosts。禁止改走未點名通道來跳過停等 |

只做「授權用盡」、該人做時卻繼續 curl＝漏渲染與憑證面。每個 HTTP 200 都叫人開瀏覽器＝膨脹。閘在「要人互動才是下一觀測」，不是凡 web 必 UI。

**碰目標前先問：指揮是否已能操作瀏覽器／遠端桌面／原生 GUI。**  
登入、MFA、SSO、OAuth/SAML、要填的 JS 表單、session 流程、檔案選擇器、UAC／credential prompt、401+Negotiate/NTLM 登入頁：預設 `UI`。  
未登入可渲染頁的第一眼：ASSISTANT 截圖（`hunt-loop.md` §2.3），不是預設把畫面丟回指揮。精確 headers／body、批次枚舉、非互動 API 走 CLI。

下列 runtime state 當 credential surface：已載入 profile、連線管理員、saved credential、masked field、token 檢視、憑證選擇器、session 選擇、consent dialog。先看畫面已經提供什麼，再考慮離線解密、逆向或長命令鏈。

`UI` 步驟必須寫清：去哪個 URL／視窗、做什麼、完成後回傳哪些 URL、畫面、錯誤、response、token 欄位或設定值。指揮說畫面與假設不符時，立刻重建模型，不要把觀察硬塞回原 CLI 假設。

禁止用一次 assistant GET／curl 充當「已經看過」一個以視覺或登入為下一觀測的面。

## 7. 高風險前檢查

在 exploit、spray、PoC、持久化或 dirty-state 前確認：

1. 目標與 scope 仍正確，服務可達
2. port、banner、版本與先前證據一致
3. 憑證／ticket／token 有效，限額不會未同意 lockout
4. CVE／PoC／technique 的適用版本與前提已即時查證（在預算內）
5. 預期效果、副作用與清理已說明

任一不成立 → 更新事實並交還指揮權，不要用舊假設繼續。

## 8. 命令格式

- 需要指揮執行的指令**全部**放進獨立 code fence；內僅純命令，不混工具標記、不混說明
- 禁止只把命令寫在散文或行內 backtick。形狀與「何時必須交指令」見 `output-contract.md` §1.3
- 缺參數先索取，不用假完整佔位符
- `ASSISTANT` 執行時直接呼叫真正工具；未到決策邊界則繼續同方向覆核，停條件一到才 HANDOFF
- 不得用 shell 分隔符把跨信任邊界或動作類升級藏成「同一方向」
- 同方向覆核可用順序依賴；跨面或升級動作類必須拆成新方向

## 9. 本地材料

僅在明確允許保存時寫入 `./pentest-state/` 子目錄。  
不要把目標材料放進 `/tmp`，不要把待執行命令寫進 `.txt`。

## 10. 執行者優先

在明確 scope 內，使用者指定具名操作時說明風險並執行；可建議更短路線，但不以偏好覆寫命令。  
scope 不清、超出授權、可能傷害第三方或更高層規則禁止時則停止並等待。

## 11. 可機械判定的授權閘（同方向／同面／授權時效／失敗兩次停）

對應 SKILL 頂部 **R1／R3／R5**。這些取代「算不算」這類判斷題。

### 11.1 同方向測試（R1 判準）

後續呼叫仍屬同一方向，當且僅當下列**全部**成立：

1. 測的是同一條賭注（同一組 expect／kill_if）
2. 動作類不升級（observe／fingerprint／read 不跳去 exploit／auth_use／spray／pivot）
3. 目標／路徑／身份要嘛寫在方向裡，要嘛只是讀回本方向剛寫入的
4. 不使用本則新拿到的秘密（R2）

任一不成立 → 新方向，必須先 HANDOFF。

- 合法同輪：POST 標記檔後立刻 GET 列表／LIST 同一組已知目錄；對已列名的三個帳號連續做同構未認證查詢。
- 非法同輪：掃到新 port → 同輪對該 port exploit；拿到 hash／票 → 同輪拿去登入；上傳成功 → 同輪改打 webroot／CA。

### 11.2 同面測試（R5 判準）

「同一目標面」= 同一 host × 同一服務／協定 × 同一 primitive 語義。對同面連續兩次**同一 error 類別**失敗，第三次禁止只換工具皮，必須 HANDOFF。工具換皮（`xfreerdp`→`rdesktop`→`Xvfb`）不產生新語義。

### 11.3 授權時效（R3 判準）

- 授權只綁「當前訊息具名的方向」。
- 「可以／繼續／好／GO／y」確認緊接在前那一個已完整描述的**整個方向**。
- **當則訊息若沒有具名方向，短詞 = 只准盤點，0 次新目標 ACT。**
- 方向的停條件一到即 STOP；不得延伸成整場 engagement 通行證。
- 沉默、模糊詞（「下一步／你看著辦」）不授權新方向。

### 11.4 失敗兩次停（R5 執行層）

計數以「同面 × 同 error 類」為單位；計數 = 2 時，下一步必須是 HANDOFF，禁止第 3 次同構嘗試。換 Goal／換軸／重驗 primitive 走 `error-recovery.md`。

### 11.5 授權動作止步點（R1 + R2 + R3 執行層）

**方向的停條件一到（成功或失敗），立即 HANDOFF。** 下列里程碑一律是決策邊界，即使「看起來像自然下一步」：

#### 11.5a Foothold 止步點

取得目標 command execution（任何形式的 RCE、shell、遠端命令通道）是**里程碑邊界**，不是新授權：

- 確認 RCE 有效的那一條命令是方向內已點名的動作。
- RCE 確認成功後**立即 HANDOFF**：報告結果 + 態勢 + 下一方向，**停止 tool call**。這是換方向、不是收工（HANDOFF 結束的是方向不是狩獵）。
- 禁止把 RCE 確認結果當授權，自行跑後續偵察或 post-exploitation。
- 後續是新方向，必須單獨取得授權。下一方向預設是該新觀看者的剩餘觀察 batch（`hunt-loop.md` §2.4），不是第一份到手材料的利用。
- 判準：拿到 command execution 後，第一個想跑的「順手多查一下」就是越界——停下，交還指揮權。

#### 11.5b Exploit 成功止步點

任何 exploit、密碼變更、認證繞過、橫向移動等使用者具名授權的動作，**成功完成後也是里程碑邊界**：

- 動作成功（API 回 success:true、命令回執行結果、密碼變更確認等）= 該授權**已用盡**。
- **立即 HANDOFF**：報告結果 + 態勢 + 下一步建議，**停止 tool call**。
- 禁止把「exploit 成功後自然產生的下一個攻擊機會」當授權。例如：
  - 密碼重設成功 → 禁止自行用新密碼登入；登入是新方向
  - 認證繞過成功 → 禁止自行用取得的 session 做 API 呼叫；那些是新方向
  - RCE 確認成功 → 禁止自行跑枚舉命令；枚舉是新方向，預設走 `hunt-loop.md` §2.4
- **判準：用新能力做事是新方向；覆核剛做完的那一探不是。** 新觀看者出現時，下一方向走 §2.4，不是該身份碰到的第一份檔。
