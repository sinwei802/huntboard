# Tactical Search — 戰術即時展開

本文件只規範**如何用搜尋把已觀測事實展開成正交賭注**。  
**不內嵌**任何具體手法、命令、payload、CVE 或題解路徑。戰術內容每次現場查。

戰役位置（何時 OBSERVE／EXECUTE／ADJUST）見 `hunt-loop.md`。  
技術細節查法見 `search-mindset.md`。  
Hunt Plan 欄位以 `scripts/hunt_plan.py` 為真源。

**戰術搜尋是研究，不是執行授權，也不是同輪開新方向。**  
**不是等 Stall 才第一次找戰術。** DESIGN 是主觸發；Stall 是賭注打盡後的補網。

---

## 1. 何時搜（三個入口）

| 入口 | 條件 | 目的 |
|------|------|------|
| **DESIGN（主）** | 觀察完成且尚無可用 Hunt Plan，或 Goal 剛換，或 HAVE／已觀測服務裡新出現目錄／域身份／命名服務 | 鑄 2–3 條排序過的賭注 + 第一探。搜尋鍵來自那些觀測，不是框架章節 |
| **ADJUST 再展開** | outcome 為 `unknown_primitive` 或 `goal_achieved` | 用新 primitive／新能力 Goal 重鑄賭注 |
| **STALL** | 活躍賭注已盡，且連續 3 步無新事實 | 找尚未進組合的戰術**類別**；仍不變則 framework-miss 或低信心候選 |

使用者「跳過 Stall」只取消第三入口，不取消 DESIGN，不帶新授權。

仍有未測觀察面或未測賭注時：**禁止**用上網代替本地否證。

---

## 2. 搜尋鍵（從獵物來，不是從框架名來）

禁止把「當前主流分類體系叫什麼」當本回合第一條 query。分類名只當**透鏡**，且僅在已觀測事實組不出 query 時才查一次（計入預算）。

依已觀測槽位組正交 query（條數上限見 SKILL.md §6.1，與本則總額共用）：

1. **產品 + 版本 + 行為／效果**（要的是可觀測能力，不是工具暱稱）
2. **primitive**（誰 — 對什麼 — 造成什麼效果 — 在哪條通道）
3. **錯誤／拒絕語義 + 環境類**（若有）
4. **身份／目錄角色**（HAVE 或已觀測服務含目錄、域身份、命名服務時必用）：用**已看到的**產品／角色／身份能力當鍵，現場搜當前 abuse surface。這是 DESIGN 主入口的搜尋鍵，**不是**等 Stall。禁止用記憶中的手法表、編號清單或「這類目錄通常先做什麼」代替搜尋。

去識別、來源層級、cache key：`search-mindset.md`。  
CTF：禁止題名 + writeup；結果必須立刻綁回已觀測產品、錯誤、身份或配置。

每條 query 先自問：結果為空或負面時，哪一條賭注會被改寫？答不出來就不要搜。

---

## 3. 怎麼把搜尋收成計畫

1. 只保留：前提、適用版本、否證條件、最小驗證一探、1–2 個來源。
2. 鑄 **2–3** 條正交賭注（不同攻擊面／信任邊界／操作軸；同軸換皮不算）。
3. **排序**：先打「成本最低、且能改變目前 Goal」的那一探。未使用的秘密 × 已點名身份／登入口算進最便宜。不得按框架章節序或記憶中的經典順序。
4. 寫入 Hunt Plan（goal／bets／next_probe／expect／kill_if）。`validate` 必須能過才能把相位標成 EXECUTE。
5. 進入 CHOOSE：下一刀 = `next_probe`；深打預設 `CONFIRM-REQUIRED`。**知道 Technique ≠ 獲得執行授權。**
6. 研究結束後 HANDOFF。同輪不得開新方向——除非使用者當則已具名授權該方向，且尚未做過本則目標動作。

### 搜尋失敗的有界處理

- 假設組合完全不變：預算內最多再 1 次 query。
- 仍不變：`framework-miss` 或標 `[?]` 的低信心候選 + HANDOFF。
- 禁止為「算完成強制搜尋」而搜到假設改變為止。

---

## 4. framework-miss

claim 無法對應出任何可檢驗的本地前提時：

- 可宣告 `framework-miss`，改搜產品／錯誤／版本行為（同一預算）。
- **同一主假設下只允許一次 miss。**
- 第二次仍無候選：交出至少一條低信心戰術賭注，或降級該主線並建議切正交線，然後 HANDOFF。

---

## 5. Stall 入口（次要）

只在 `hunt-loop.md` 的 ADJUST 得到 `stall`（活躍賭注已盡）且連續 3 步無新事實時走本節。先確認觀察已完、沒有未測賭注。

此時用 1 個（最多 2 個）戰術**類別名**當附加透鏡，目的仍是鑄新賭注，不是下載 exploit。其餘規則同 §3。

---

## 6. 禁止

- 內嵌或背誦具體利用步驟、命令模板、題解路徑
- 把框架名稱或 Technique 專名當主假設（無本地證據）
- 用戰術搜尋拖延補觀察面或未測賭注
- 將搜尋結果當成 `PRE-AUTHORIZED` 目標動作
- 為「假設必須改變」超過回合搜尋預算
- 觀察未完成就 DESIGN 來假裝有戰術
- HANDOFF 後繼續 tool call
