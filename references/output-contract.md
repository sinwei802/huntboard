# Output Contract — 口語輸出與停等

## 1. 預設格式

模板真源在 `SKILL.md` §7（新事實／判斷／態勢／2–3 條選項）。本檔寫欄位怎麼填、短詞綁哪一條。

每條選項必填四欄：

- **做什麼**：測哪條賭注、允許哪些動作類、用哪個身份／工具
- **預期**：成功長什麼、失敗長什麼（含 Guest 回落、lockout、must-change 怎麼認）
- **風險／停**：限額、何時停、要不要清理
- **為什麼現在**：改哪個 Goal、相對其他選項的成本

選項 1 標 `[建議]`，且必須帶 `[EXECUTOR | APPROVAL]`（R7）。「繼續／打／好／GO／y」只確認選項 1。點名 2 或 3 才換方向。

禁止只交「回打或繼續」的是非題。禁止把未完成觀察攤成請指揮發明的缺口選單。前線出已排序計畫，指揮審的是 cons。

- 對指揮的選項欄遵守 §1.1，不是越短越好
- 可列舉掃描結果先表，見 §1.2；「不重印完整狀態表」指內部 Hunt Plan／卡表，不是禁止開埠表
- 禁止電報文
- **輸出選項欄 = HANDOFF = 本回合結束；之後禁止 tool call**
- 作業脈絡必須滿足授權與 H1／H2／H4；不必把卡表印給指揮
- 若判斷升級或未用秘密重用更能改 Goal，必須寫進選項並可當建議，不得只給低權限變體。提出≠執行。
- 未登入視覺：HANDOFF 給 `./pentest-state/loot/screenshots/` 的路徑，executor 可為 `ASSISTANT`。要登入／點選／MFA 才是 `[UI]`（或 `USER`），並寫回傳哪些畫面／欄位。禁止寫成「再 curl 一次就算看過」。禁止把圖灌進模型（SKILL §7）。授權用盡而下一刀仍可是 CLI 時，才用 `ASSISTANT`。兩種味道見 `execution-contract.md` §6；截圖習慣見 `hunt-loop.md` §2.3。

## 1.1 對指揮的用語（能力落差）

指揮是決策者，不是跟你同級的操作員。執行者技術較強時，回報要遷就指揮能一次聽懂的密度，不能用內部密語交差。

- **先人話，再術語。** 每一欄先寫：這輪看到什麼、為什麼重要、接下來要試什麼。術語第一次出現，用括號或下一句解釋（例：執行者＝真正去跑這個檔的那個程式或服務）。
- **一句一事。** 禁止為了短，把兩個以上獨立判斷疊進同一句。
- **停在能複述。** 指揮看完應能用自己的話複述那三點。還不能複述＝寫太密，重寫後再交。
- **命令與識別名保持原樣。** 路徑、帳號、工具參數、錯誤字串不要意譯；要解釋的是它們代表什麼。
- **不要把內部閘門當正文。** 不要對指揮唸 H1–H4、R1–R8 編號當說明；用那條規則的人話。
- **台灣口語繁中。** 像坐在旁邊跟指揮講。短句，動詞直接講那個動作。工具名、CVE、路徑、帳號、錯誤字串、指令保持英文，不翻譯。英文術語第一次出現，下一句講它在這台機器上是什麼。
- **只約束講給指揮聽的正文。** 欄位名（新事實／判斷／態勢／選項）、`[EXECUTOR | APPROVAL]`、`[CONFIRM-REQUIRED]`、code fence 裡的命令、狀態檔，維持原樣。先下定義再分段若出現在欄位裡的句子，才算踩線。
- **禁骨架，不禁單字。** 對指揮的正文禁止這些句型：本質上、這就是為什麼、並非 A 而是 B、值得注意的是、綜上所述、從而、在…的情況下、對…而言、先下定義再分段。空動詞加名詞化同樣禁：進行掃描、基於上述觀察、針對此問題、實現目標、確保流程。`針對 445`、`針對這台` 這種對著具體埠或主機講，可以留。
- **比喻詞不要拿來對指揮講。** 對齊、維度，以及拿意圖、特徵、標籤當比喻，不要寫進正文。授權標籤照寫。service fingerprint 的「特徵」、opening 腳本印出的「意圖」，留在機器裡。
- **用台灣用詞。** 資訊、伺服器、預設、品質、軟體。不要寫成信息、服務器、默認、質量、軟件。

❌ 「H4：缺名未觀測，換執行者非法，改測另一寫入面。」  
✅ 「我們已經能在那個資料夾裡放新檔，而且那邊本來就有一個會自己啟動的程式。下一刀應先問：這個程式啟動時還會去找哪個現在不存在的檔名。現在改去打別的登入或另一個共用資料夾，等於換了一個來跑檔案的角色，這一步先不做。」

❌ 「本質上，這一輪的觀察結果顯示目標在 445 上暴露了 SMB。基於該特徵，我們可以進行進一步的指紋識別，以確保後續路徑與當前意圖對齊。」  
✅ 「445 開著，是 SMB。下一刀用 nmap 的 smb scripts 看版本、有沒有簽章。版本對上之前，先不挑 CVE。」

## 1.2 可列舉掃描結果用表（Obsidian）

這一輪新事實若是可列舉列（開埠、服務／版本、未登入身份欄位、share、vhost），HANDOFF **先**放一個 `markdown` 程式碼區塊，再接選項欄。區塊內是 GitHub-flavored markdown 原文（標題+表），指揮從區塊一鍵複製、貼進 Obsidian。表不取代選項欄。

**必須**用 code fence。渲染出來的表複製不到可用的 `|` 原文。禁止只渲染表。禁止回「去開某個 md」來拿表。禁止只把表寫進本地檔卻不在對話區塊裡出同一份原文。本地 checkpoint 是副駕駛記憶，不是貼上來源。

傳輸面標題與欄位真源：`port-scan-pipeline.md` §4。其他可列舉面用同一規則：一列一物件，欄名固定、值保持原樣。沒有列就不建空表。

## 1.3 互動：指揮要跑的指令

凡是需要指揮自己執行的指令（`[USER]`、風險卡裡的命令、寫 `/etc/hosts`、VPN、複製即跑），**全部**放進 code fence。說明、預期、風險寫在區塊外。區塊內只放可複製的純命令，不混工具標記、不混中文解釋。掃到本機還解析不到的已宣告名字時，hosts 命令不得省略，也不得改寫成 Host 標頭替代方案。

同一方向有多條命令：可以一個 fence 裝全部，或一條一個 fence。禁止漏一條只寫在散文裡。禁止只用行內 backtick 當交付。缺參數先索取，不用假完整佔位符。命令純度真源：`execution-contract.md` §8。

## 2. 何時可以更短

純確認、純澄清、拒絕非法 batch：一兩句完整話——仍算 HANDOFF，同樣停止 tool call。  
checkpoint 保存完：停在態勢，**不加選項、不綁下一刀**。  
`CONFIRM-REQUIRED` 的風險寫進選項的「風險／停」；不必再重複一張獨立風險卡。

## 3. Stall

依 SKILL.md 與 `stall-breaker.md` 輸出診斷，再接 §7 選項欄。  
盤點只針對當前主假設的 scope，不貼無關領域清單。  
最小否證當建議選項，預設 `CONFIRM-REQUIRED`；不要在診斷後直接執行。

## 4. 跳過 Stall

明示：診斷未完成；不把未證成結論當事實；下一步單獨標授權；本回合預設不 ACT。

## 5. 拒絕跨方向

說明為何跨了信任邊界、升級了動作類、或要用本則新秘密，改寫成一個具名方向，**本輪不執行越界部分**。

## 6. 風險確認卡

approval 非 `PRE-AUTHORIZED` 時，寫進該選項的「風險／停」（然後**等待**）。需要時加：清理、回傳（UI／USER 要貼回的畫面、URL、欄位或錯誤）。

若這一步需要指揮跑指令：該選項之後另開 code fence，把該跑的命令**全部**放進去（§1.3）。沒有 fence 視同沒把指令交給指揮。

輸出後 **0** 目標 tool call，直到使用者下則訊息明確授權。

## 7. Triage

CRITICAL／HIGH／MEDIUM／LOW 只影響回報排序，不形成執行授權。

## 8. 搜尋／研究回合

若本回合只做了有界搜尋或本地分析、沒有目標 ACT：

- 新事實：寫清查到什麼、來源層級（官方／模組／文章）
- 判斷：如何改假設組合
- 選項：2–3 條可執行提案，建議那條帶正確 APPROVAL
- 然後停止，等使用者

## 9. 態勢列（可選；戰役要記住時才印）

Hunt HANDOFF 的態勢列印在選項之前，下一探填建議那條的短名：

```text
態勢：Goal=<能力語言> · 下一探=<建議那條的短名>
```

Phase 只寫進 warboard／`hunt_plan.py`，不印給指揮。可加 `主賭=`、`attempts=`、`未測軸=`、`調整=`、`HAVE=`、`wildcard=`。Goal = 能力語言，不是工具名。選項 1 必須完整到「繼續」就能打完（R3）。

## 10. 回合結尾

HANDOFF 前對一下 SKILL 頂部 R1–R8、H1–H4、§7 選項欄。不要把閘門編號唸給指揮。踩線就改寫再交。
