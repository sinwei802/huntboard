# Stall-Breaker — 卡點診斷（提案，不自動執行）

核心觸發在 SKILL.md。本文件補程序紀律。戰役相位見 `hunt-loop.md`；戰術搜尋細節見 `tactical-search.md`。

## 觸發

連續 3 個已完成 STEP 的 outcome 皆非 `fact_gained`／`new_surface`。  
同一已測軸上的變體失敗，不計。  
Hunt Plan 仍有活躍未測賭注或觀察面未完 → **不是**本流程；補那一注／那一面（H1／H3），不要上網裝忙。

## 「跳過」語義

只取消本流程（含條件性的戰術搜尋）。  
不批准 batch、不批准新動作、不把未完成診斷寫成事實。

## 終態（硬規則）

Stall-Breaker 的產品是：

1. 口語診斷（步驟 1–4）
2. **一個**最小否證測試當建議選項（步驟 5）
3. §7 選項欄 HANDOFF（建議 + 1–2 條正交備選）

- 提案預設 `[EXECUTOR | CONFIRM-REQUIRED]`。
- **本回合不得執行**該否證測試，除非使用者**當前訊息**已具名授權該測試。
- 診斷完成 = 可以 HANDOFF，**不是**可以連打命令。
- 受 SKILL.md 頂部 R1／§6 回合邊界與搜尋預算約束。

## 步驟 0｜戰役預檢

依序問，命中就離開本流程：

1. 觀察未完（`observation_gaps` 非空）→ 相位 OBSERVE，下一探補缺口。
2. 沒有 Hunt Plan 或 Goal 空 → 相位 DESIGN，走 `tactical-search.md` 主入口。
3. 仍有活躍賭注未打 → 下一探 = 該注的 probe（next-bet），不是 Stall。

以上皆否，才進入步驟 1。

## 步驟 1｜宣告

用能力語言寫出當前主假設（Goal + 主賭），不要寫工具名。

## 步驟 2｜盤點（抽象）

只針對**當前主假設自己的前提與操作邊界**列出：

- 已測什麼
- 明確尚未測什麼
- 哪些前提仍未驗證

維度必須從該假設的 claim scope 推導。  
**禁止**貼上與當前假設無關的固定領域清單。

## 步驟 3｜過早關閉

若準備寫下的關閉語句 scope 大於已測維度 → 判定 overclaim。  
下一步優先**提案**補未測維度，不得大跳轉，也不得用上網代替本地否證。

## 步驟 4｜分支

### A. 仍有未測維度

- 替代假設與下一步以**補未測維度**為主
- 可記錄「稍後戰術搜尋」，但**不得**用戰術搜尋取代本地否證
- 本步以本地推理為主；不為了「看起來有在做事」而開搜

### B. 無未測維度

- 可搜尋且預算仍有餘額：走 `tactical-search.md` 的 STALL 入口（計入 SKILL.md §6.1 同一回合總額）
  - 搜尋鍵仍從已觀測產品／primitive／錯誤來
  - 必須回扣 Hunt Plan、宣告 framework-miss、或交出低信心候選後 HANDOFF
- 預算不足或無搜尋能力：輸出去識別 Query Pack + 診斷，**HANDOFF**，不得超預算狂搜
- 再產生正交替代假設與最小否證**提案**

## 步驟 5

- 替代假設必須能被不同的最小測試區分（同軸換皮不算正交）
- 否證測試優先挑戰主假設；成本最低、可觀測
- 最小否證寫進建議選項；其餘正交賭注當選項 2／3
- 預設 `CONFIRM-REQUIRED`；標明目的是挑戰哪條假設

## 輸出骨架（口語）

```text
目前卡住了：主假設是 <X>，已經連續三步沒有新的重要事實。
相位：ADJUST／stall

與該假設相關的已測／未測：
- ...

過早關閉檢查：
關閉 scope 是否大於已測？<是／否>，因為 <理由>。

分支：<補維度 / 戰術搜尋 / framework-miss / Query Pack>

替代假設（主線可能為錯）：
- <正交一條>

新事實：<本回合診斷得到的整理，不是新授權>
判斷：<為什麼建議換測法／換軸>
選項：
1. [建議] [ASSISTANT|USER|UI | CONFIRM-REQUIRED]：<一個最小否證測試；等指揮批准>
   預期：…
   風險／停：本回合不執行，除非當則已點名
   為什麼現在：成本最低、能挑戰主假設
2. [ASSISTANT | CONFIRM-REQUIRED]：<正交備選>
   預期：…
   風險／停：…
   為什麼現在：…
```

跳過時：一句話承認診斷未完成，再交 §7 選項欄；仍不自動 ACT。
