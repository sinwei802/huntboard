# Search Mindset — 查詢心法

技術細節不在此寫死，靠即時搜尋。  
搜尋是**有界研究**，不是無限 tool loop。預算與回合邊界以 SKILL.md 頂部 R1／§6 為準。

## 1. 何時搜尋

搜尋是正常路徑，不是例外。以下可觀測事件觸發搜尋（不靠自我評估「我知不知道」）：

- 出現 error code 或未知錯誤訊息 → 查含義、原因、現成解法
- 連續兩次同類失敗（R5）→ 查 error + 環境 + 現成工具（預算豁免，見 SKILL.md §6.1）
- 下一步涉及手寫通用能力的程式碼 → 先查是否已有現成工具
- 決策依賴版本行為、適用範圍、工具語法等可能已過時的細節且 cache miss
- 觀察完成、要鑄或重鑄 Hunt Plan（DESIGN）
- Stall 且賭注已盡、需要能**推翻**主假設或建立正交戰術類別的公開資訊

## 2. 何時不該搜尋

- 已有足夠一手證據可 CHOOSE
- 純本地狀態分析
- 用搜尋拖延換假設（明知應正交轉向，卻搜「怎麼把同一條路再做久一點」）
- 本回合搜尋預算已用盡 → 綜合並 HANDOFF
- tool 結果剛返回 → **禁止**再開一輪搜尋；只 INTERPRET + H3 → HANDOFF。**唯一例外**：本則剛完成觀察且預算仍有，可做 DESIGN 搜尋（研究，不得再碰目標）

## 3. 搜尋前自問

1. 我真正缺的是什麼？
2. 目的是支持還是試圖推翻主假設？
3. 若結果為空或負面，假設如何變？
4. 本回合還剩幾個 query 額度？

禁止無目的「先搜看看」。禁止把「當前主流分類體系叫什麼」當本回合第一條 query。

## 4. Query 設計與預算

- 正交 lens：版本／build、行為或 primitive、相鄰系統或控制面
- 每則訊息的 query 上限、抓取份數、超預算怎麼停：見 SKILL.md §6.1，此處不重抄數字
- tactical-search 與 taxonomy 確認 query **全部計入**同一預算
- 超預算：立即綜合結論並 HANDOFF，禁止繼續搜
- 去識別化：去 IP、hostname、組織名、憑證、token、客戶識別
- 優先：官方／advisory／原始碼 > 維護中模組 > 一般文章
- 禁止「存在 technique」＝「目前環境可利用」

### Cache（作業脈絡）

以 `產品｜版本/build｜primitive｜問題｜lens` 為 key。  
同 key 直接重用；版本、patch、primitive、問題或新反證改變才失效。

## 5. 結果評估與相位

- 是否改變任一假設信心？
- 是否只是確認偏見？
- 版本與前提是否核對？
- 評估完 → 更新假設 → CHOOSE **一個**下一步 → **HANDOFF**  
- 搜尋結果**不得**同輪自動觸發目標 ACT

## 6. Stall 時的搜尋優先

1. 能推翻主假設的證據
2. 有助建立正交假設的戰術**類別**
3. 不優先搜尋「如何延長當前已失敗軸」
4. 假設未變：最多再 1 query；仍不變 → miss／低信心候選 + HANDOFF（見 `tactical-search.md`）

## 7. 無搜尋能力或預算將盡

輸出去識別 Query Pack：

```text
Lens | Query | Purpose | 期望證據
```

交使用者代查，然後 HANDOFF。  
不以「無法搜尋」為由對目標連打，也不以「無法繼續」結束而不交還指揮權。
