# http-observe-only

對齊學習：20260926 下一週 Web：HTTP 解剖與只觀察偵察

## 何時用

- 相位：初勘／Web 面剛出現（有 HTTP(S) 服務或反向代理跡象）。
- 觸發：拿到 URL／Host／狀態碼家族，但**尚無**授權下的利用決策。

## 要驗證什麼

1. 一次完整往返能否用自己的話復述（方法、路徑、狀態、至少兩個標頭、有無 Cookie／Session 線索）。
2. 目前觀察是否仍完全落在**授權範圍**（自有 lab／已授權平台帳號內）。
3. 「只觀察」是否已窮盡到值得換假設，而不是還沒看完就升級動作。

## 證據長什麼樣

- 請求線與回應線各至少一筆可複核紀錄（欄位表即可）。
- 標頭能區分：內容類型、虛擬主機、快取／代理、認證挑戰（例如 WWW-Authenticate 有無）——**只描述存在與否與類型**，不寫繞過法。
- 目錄／頁面枚舉結果：空、薄、或有命名空間——記「覆蓋範圍」，不記攻擊腳本。

## 何時離開本卡

- 已能列挑戰／任務／scoreboard 盤，或已完成一次完整往返＋穩定業務 API 指紋 → **離開只觀察**，改載 `web-app-evidence-ladder`／`challenge-board-handoff`，交可稽核下一階 HANDOFF。
- 禁止在挑戰盤已入 HAVE 後仍只提案「繼續 fingerprint」。

## 死路怎麼標

- **授權邊界死路**：目標或路徑超出授權 → 標記 `DEAD:auth-boundary`，停止對該主機繼續探測。
- **資訊面死路**：landing 幾乎無內容、枚舉無穩定新路徑、無認證挑戰也無可跟的業務物件 → 標記 `DEAD:http-thin`，改查其他端口／協定面，不對 Web 硬升級。
- **觀測不足**：連一筆完整往返都記不清 → 不進入下一相位；退回本卡重做。

## 去哪查

- 公開概念：HTTP 語意（方法、狀態碼家族）、Cookie 與 Session 差異（MDN、RFC 9110 級文件）。
- 學習篇：20260926 下一週 Web：HTTP 解剖與只觀察偵察。
- **不查**：writeup 解題路徑、可照做的利用文章當「下一步指令」。

> 紅線：無 payload／PoC／逐步利用。
