# session-break-rebuild

> **繁中**：Session 斷裂重建：remount／清 cookie 後不得假設舊態仍有效。


## 何時用

- lab／容器／box remount、path-wipe、服務重起、明確「舊 cookie／JWT／籃子不可假設有效」。
- 重登失敗、帳號可能隨 volume 重來而消失時。

## 要驗證什麼

1. 戰情**先記斷裂**（時刻＋污染標記），再動下一動作。
2. 舊 session：whoami／關鍵資源若仍「像活」，仍**不當作戰有效**，直到指揮批「重建」。
3. 重建選項只走授權：重登 →（失敗且獲批）重註冊 → 再做只讀對照；每步記狀態碼與是否拿到新工作階段事實。
4. 重建完成前：不延續 remount 前的利用／改單假設。

## 證據長什麼樣

| 元件 | 合格 |
|---|---|
| 觀測 | 401／空籃／容器重起紀錄／舊 token 與新行為矛盾 |
| 解釋 | 「session 斷裂，需重建」而非「服務壞了隨便換招」 |
| 可否複核 | 他人能依戰情重做登入／註冊判斷 |

## 死路

- 重登失敗且**未批**重註冊 → `DEAD:await-reregister-auth`，停；不自建帳、不噴射。

## 禁

- 把基礎設施斷裂當成「技能不會 Web」的唯一結論；也禁止為求達標略過重建證據。
